## Summary

`plotBZ_V1` constructs direct and reciprocal primitive vectors for the 14 Bravais lattice settings offered by the GUI. It builds a finite reciprocal lattice, uses Voronoi cells as bulk first Brillouin zones, and draws 3-D cells or their horizontal and vertical sections. A separate path projects bulk reciprocal vectors to obtain a 2-D surface lattice and draws its Voronoi cells. The reciprocal-vector formula includes the expected `2*pi` factor and is sound for valid, nondegenerate direct cells. The default GUI and all four plot callbacks ran in the local MATLAB installation.

The most consequential issue is the **surface basis selection**: choosing two short vectors from the three projected bulk primitive vectors does not always generate the full surface reciprocal lattice. For a primitive cubic `(234)` surface, the plotted reciprocal-cell area is twice the correct value. The section helper also rejects a legitimate three-vertex polygon. Input validation is insufficient: `(000)` Miller indices produce `NaN` surface vectors, and other invalid lattice parameters can reach Voronoi and graphics calls.

## Findings, in priority order

### P1 — Surface reciprocal basis can omit lattice points

**Code:** [surface vector selection](../Visualization/plotBZ_V1/plotBZ_V1_surface_realtime_vector.m#L16-L33), then [surface Voronoi construction](../Visualization/plotBZ_V1/plotBZ_V1.m#L809-L825).

The helper projects the three bulk reciprocal primitive vectors, sorts by squared length, discards a zero vector if it sees one, and picks the two shortest nonparallel vectors. Nonparallel projected vectors need not be a **primitive** basis of the projected lattice. Their integer span can exclude points generated by the third projected vector. The 2-D Voronoi polygon then has the wrong area and boundaries.

For primitive cubic `(234)`, the helper chooses the projections of `b3` and `b2`. In that chosen basis, the projection of `b1` has coordinates `(-2,-1.5)`, so it is absent from the generated lattice. With `a=3.1416` (the GUI default), the calculated cell area is 1.48556 instead of 0.742778. Analytically, the primitive surface real-space cell area is `a^2 sqrt(29)`, hence the reciprocal area is `(2*pi)^2/(a^2 sqrt(29))`.

**Improve:** derive a primitive 2-D basis of the projected 3-D integer lattice, for example by an integer-lattice reduction/Smith or Hermite normal-form step followed by 2-D basis reduction. A simpler implementation can enumerate projected integer combinations, identify a shortest independent primitive pair, and verify that all three projected generators have integer coordinates in that pair. Add area checks for high-index planes, including `(234)`.

### P1 — Three-vertex sections are dropped, and section errors are hidden

**Code:** [intersection helper](../Visualization/plotBZ_V1/plotBZ_V1_intersectBZ.m#L8-L36).

The code proceeds only when `length(intersectionPoints)>3`. A convex polyhedron can have a legitimate triangular intersection. The tested cube/plane case yields exactly three crossing points and an unassigned output. The enclosing `try` has no `catch`, which can conceal geometry failures in the plot callbacks and makes debugging difficult. The edge-crossing logic also needs an explicit policy for a plane through a vertex or along a face; a strict below/above classification alone does not resolve such cases.

**Improve:** accept at least three *unique, non-collinear* intersection points, use a tolerance when classifying vertices on the plane, and return an empty edge array for no section. Remove the silent `try`, or catch a specific expected geometry exception and report it with context. Test triangular, quadrilateral, tangent, and coplanar cases.

### P1 — Crystal and plot inputs are not validated

**Code:** [field parsing](../Visualization/plotBZ_V1/plotBZ_V1_construct_rec_lattice_vectors.m#L11-L19), [reciprocal divisions](../Visualization/plotBZ_V1/plotBZ_V1_construct_rec_lattice_vectors.m#L127-L143), [lattice ranges](../Visualization/plotBZ_V1/plotBZ_V1_construct_bulk_rec_lattice.m#L4-L14), [surface projection](../Visualization/plotBZ_V1/plotBZ_V1_surface_realtime_vector.m#L3-L18), and [figure/line-width parsing](../Visualization/plotBZ_V1/plotBZ_V1.m#L789-L825).

Text fields are converted without finite-value or domain checks. Zero/negative lengths, impossible combinations of `alpha`, `beta`, and `gamma`, zero cell volume, `(000)` Miller indices, reversed or noninteger range endpoints, and malformed figure numbers or line widths can flow into division, allocation, Voronoi, or plotting. The tested `(000)` case produces `NaN` vectors. `str2num` is also used for line widths, figure number, and index buttons; it evaluates MATLAB expressions instead of parsing a scalar number.

**Improve:** parse scalars with `str2double`; reject `NaN`/`Inf`; require positive lengths, a physically valid positive-definite Gram matrix and nonzero primitive cell volume, integer Miller indices with a nonzero vector, ordered integer plot ranges, positive finite line widths, and valid figure numbers. Put these checks in a single input-parsing function and display a field-specific GUI error before any geometry work.

### P2 — Fixed Voronoi padding is not guaranteed for skew lattices

**Code:** [3-D range padding](../Visualization/plotBZ_V1/plotBZ_V1_construct_bulk_rec_lattice.m#L13-L25) and [2-D range padding](../Visualization/plotBZ_V1/plotBZ_V1_construct_surf_rec_lattice.m#L8-L16).

The bulk calculation adds three lattice indices on each side and the surface calculation adds two. These are empirical limits, without a proof that all Voronoi-defining neighbors are included for every allowed skew or nearly degenerate cell. The preallocation expression also contains a confusing `*+` sequence. Larger user ranges make `voronoin` operate on the entire padded cloud even when only a few zones are requested.

**Improve:** reduce the reciprocal basis and construct each zone from relevant bisector half-spaces, or grow the neighbor shell until the selected cells are bounded and unchanged. Cache the reciprocal lattice and Voronoi result across callbacks when only display parameters change. Add skew-cell tests and a practical range/point-count limit.

### P2 — Clearing a target figure can erase unrelated overlays

**Code:** [2-D clear buttons](../Visualization/plotBZ_V1/plotBZ_V1.m#L773-L781), [3-D clear button](../Visualization/plotBZ_V1/plotBZ_V1.m#L1239-L1249).

The clear callbacks find and delete all line objects in the selected figure, and the 3-D callback also deletes all patches. The manual explicitly describes plotting BZ outlines over measured data. If that data is drawn with line or patch objects, Clear removes it too. Figure numbers are user supplied, so a mistaken number can target another figure.

**Improve:** tag BZ-created graphics with an app-specific identifier or retain their handles and delete only those handles. Validate and show the target figure before a destructive clear action.

### P2 — Plotting and physics are tightly coupled to GUIDE controls

**Code:** [GUI entry point](../Visualization/plotBZ_V1/plotBZ_V1.m), [reciprocal-vector helper](../Visualization/plotBZ_V1/plotBZ_V1_construct_rec_lattice_vectors.m#L1-L26), [surface-vector helper](../Visualization/plotBZ_V1/plotBZ_V1_surface_realtime_vector.m#L1-L35).

The numerical helpers read GUI handles and some write computed vectors back into controls. The large GUIDE file repeats lattice construction, Voronoi calls, color selection, and axis preservation across plot callbacks. This makes physical geometry difficult to test independently and repeats expensive work. Many generated callbacks are empty, contributing to the 422 Code Analyzer notices.

**Improve:** extract pure functions for validated lattice parameters, reciprocal vectors, primitive surface basis, Voronoi cells, and plane sections. Keep callbacks responsible for input collection and graphics. Share the plotting options and cache geometry by input state. Retain GUIDE as a front end initially; consider a UI migration only after geometry behavior is covered by tests.

### P2 — Dependency and coordinate conventions need documentation

**Code:** [rotation to plotting frame](../Visualization/plotBZ_V1/plotBZ_V1_bulk_realtime_vector.m#L2-L16), [surface rotation](../Visualization/plotBZ_V1/plotBZ_V1_surface_realtime_vector.m#L3-L15), [horizontal offset](../Visualization/plotBZ_V1/plotBZ_V1.m#L1094-L1100).

The code aligns the selected reciprocal normal with plot `kz`, applies another in-plane rotation, and uses `shi2DhBZ/100` times the full `g_hkl` as the horizontal plane position. The displayed axes therefore describe a rotated plotting frame; `shi2DhBZ` is a percentage of that reciprocal vector's magnitude, not an absolute `Å^-1` value. The GUI's `rotx`/`rotz` dependency on Phased Array System Toolbox is not stated in the README. The bundled `matGeom` dependency is present in setup but its role in this GUI is not described to users.

**Improve:** document the orientation convention, angle signs, units (`a,b,c` in Å and reciprocal coordinates in `Å^-1` if that is the intended input), whether Miller indices use conventional or primitive reciprocal vectors, and the meaning of the horizontal-offset field. List Phased Array System Toolbox and `matGeom` as plot-BZ requirements, or replace the simple rotation calls with local rotation matrices to remove the former dependency.

## Suggested verification work

1. Add pure numerical tests for `a_i dot b_j = 2*pi*delta_ij`, positive cell volume, expected first-zone volumes, and known cubic/FCC/BCC/hexagonal BZ shapes. Use both conventional and primitive Miller-index modes for centered cells.
2. For surface zones, compare the generated reciprocal-cell area with `(2*pi)^2/A_surface` for `(001)`, `(110)`, `(111)`, and high-index `(234)` cubic planes; check that every projected bulk reciprocal generator has integer coordinates in the chosen surface basis.
3. For plane sections, test triangle, quadrilateral, no intersection, vertex contact, and face-coincident cases. Check that an empty section returns an empty array without an exception.
4. Add a small GUI smoke test with isolated figure numbers and explicit cleanup of only its own graphics. Test overlay and Clear behavior on a target axes containing a separate data line.
5. Benchmark increasing lattice ranges after the geometry fixes, recording point counts, elapsed time, and peak memory. Use that evidence to set practical range limits and decide whether caching or half-space construction is needed.

## Recommended order

Fix the surface primitive-basis construction and triangular-section handling first, since they can silently change the physical result. Add input validation next. Then protect figure overlays, document the coordinate and dependency contract, and refactor the numerical core so the geometry can be regression-tested independently of GUIDE.

## Implementation record — 16 November 2026

### Changes made

1. Replaced the short-vector heuristic with [primitive integer-lattice reduction](../Visualization/plotBZ_V1/plotBZ_V1_primitive_surface_basis.m). The selected normal is expressed in the primitive bulk reciprocal basis, its integer relation is isolated with extended gcd and a unimodular transform, and the two remaining generators are reduced in 2-D. [The GUIDE-facing adapter](../Visualization/plotBZ_V1/plotBZ_V1_surface_realtime_vector.m) now only handles plotting-frame rotation and vector display. A hexagonal 60-degree tie initially made Gauss reduction oscillate; the algorithm now terminates at the tie, and a regression test covers it.
2. Rewrote [plane intersection](../Visualization/plotBZ_V1/plotBZ_V1_intersectBZ.m) to collect edge crossings and on-plane vertices with a scale-aware tolerance, remove duplicate points, accept three-vertex sections, return an empty `0-by-6` edge array for tangent/disjoint cuts, and let unexpected errors surface. Coplanar face sections are supported.
3. Added [central scalar validation](../Visualization/plotBZ_V1/plotBZ_V1_parse_scalar.m). Lattice construction now checks positive lengths, angles in `(0,180)` degrees, a positive-definite cell metric, positive cell volumes, integer nonzero Miller indices, and a supported lattice choice. Plot callbacks validate figure numbers, rotations, offsets, and positive line widths; range constructors validate ordered integer bounds. All `str2num` calls in this module were removed.
4. Replaced fixed ±3/±2 shells with [basis-dependent padding](../Visualization/plotBZ_V1/plotBZ_V1_lattice_padding.m). The bound uses half the sum of basis-vector lengths as a covering-radius upper bound, then includes all sites close enough to define a Voronoi facet. [Bulk](../Visualization/plotBZ_V1/plotBZ_V1_construct_bulk_rec_lattice.m) and [surface](../Visualization/plotBZ_V1/plotBZ_V1_construct_surf_rec_lattice.m) site lists are generated with `ndgrid`; a 50,000-site limit gives a clear error for impractical inputs.
5. Changed Clear to remove only [tagged BZ graphics](../Visualization/plotBZ_V1/plotBZ_V1_clear_graphics.m), marked by [the plotting callbacks](../Visualization/plotBZ_V1/plotBZ_V1_tag_graphics.m). Clearing no longer creates a missing figure or deletes unrelated lines and patches. Shared popup-colour mapping was extracted to [one helper](../Visualization/plotBZ_V1/plotBZ_V1_popup_color.m). Added comments near the plotting-frame rotations, plane offsets, graphics tagging, and the integer-lattice construction.
6. Documented units, axes, Miller-index mode, horizontal-offset semantics, Clear behavior, `matGeom`, and Phased Array System Toolbox in the [manual](../Manual/Manual.md) and [README](../README.md). Changed `.gitignore` so this report can be tracked while the other existing `doc` files remain ignored.

### Style and professionalism assessment

The numerical helpers now have H1 help lines, explicit contracts or invariant comments, validated inputs, consistent naming in new code, vectorized lattice construction, and no Code Analyzer notices. The GUI's shared colour mapping and tagged graphics handling remove repeated hand-written blocks. The `.fig` file still binds to the historical GUIDE callback names and signatures, so the 391 unused-argument notices were left in place; changing them wholesale would risk breaking saved callback bindings for little benefit.

The geometry is now testable without driving the GUI. A full visual comparison against representative measured ARPES overlays remains to be done. The tool still uses Phased Array System Toolbox rotation functions, now documented. Voronoi geometry is recomputed on each plot callback; measured default callback times were below one second in this environment, so caching was not added without a demonstrated performance need. The 50,000-site limit protects the GUI from unusually large or highly skewed requests, which now fail with a specific message rather than attempting an unbounded allocation.
